# HHaus intake database authority

`schema.sql` is the declarative PostgreSQL authority for both the primary HHaus database and the HHaus Supabase database. `supabase.sql` is the managed-service overlay that provisions the private upload bucket without weakening Storage RLS.

Use `declarative-postgres-migrate` (`dpm`) to create and verify ordered migration SQL. The application, web server, API server, and ORM packages must never run schema migrations.

```bash
scripts/dpm.sh bootstrap "$SHADOW_DATABASE_URL" migrations/202608300001_hhm_intake.sql
scripts/dpm.sh verify "$TARGET_DATABASE_URL" "$SHADOW_DATABASE_URL"
```

The checked-in bootstrap migration was generated by `dpm` and must converge before review. CI applies both the declarative authority and the generated migration to independent PostgreSQL databases and exercises their points-ledger, immutability, and fail-closed RLS behavior.

The Diesel schema and SeaORM entities are generated artifacts. Regenerate them from a temporary database materialized from `schema.sql`; do not hand-edit them as competing authorities.

The operational platform schema is a separate immutable adoption lane. Its
generated SQL and Rust projections are vendored under
`vendor/hhm-interfaces/platform` from the exact production interface revision;
its ordered generated and PostgreSQL-hardening migrations are documented in
`docs/platform-persistence.md`. Do not merge platform objects into this intake
authority or reinterpret legacy `hhm_reservations` as the generated
`hhm_space_reservations` table.
